Create or manage this user's scheduled tasks. Use op=list to inspect existing plans before changing one; use its triggerId for pause, resume, delete, run_now or reschedule. With op=create (default), schedule a future task only when the user asks you to do something later. For a fixed reminder, set reminder to the exact message and goal to its short description; this delivers without running a model. For work that needs app or web operations, omit reminder. Use at for a one-time or fixed-interval start; use repeatAt with repeatZone and optional weekdays for a daily/weekly local clock time, so daylight-saving changes do not shift the clock time. A condition is checked first with read only web and sandbox tools; by default the task runs only when the condition becomes met. Choose notifyWhen by what the user wants: for a routine check of how things are each time (e.g. tell me each morning if it will rain), set notifyWhen=each_time_met so every met check runs the goal; for watching for a change (back in stock, a price drop), keep the default becomes_met. Each check records a key value; the baseline is the value from the last time the goal ran, or from the first check if it has not run yet, so write comparisons against the baseline (e.g. dropped by more than 50 from the baseline). Set cooldownMinutes when the user limits how often to hear about it or the value may flap around a threshold; a cooldown no longer than the check interval has no effect, so leave it out then. Set whenIdle when the user wants the task to wait for an idle period after that time. Do not claim that a future task is arranged until this tool succeeds.
