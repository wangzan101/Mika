## 目标检查

- JVM：启动缺前帧、真实缺文件、旧记录、同一轮多动作、无截图、阶段与关键页去重。
- 导出：中文、表格、列表、链接、XML 特殊字符；DOCX ZIP/XML 结构，MD 原文保留、TXT 无样式标记。
- 真机：现有小红书任务回放、报告排版，控制区和完整图片同时可见；手动/自动过渡、倍速、阶段导航、返回、三种导出。
- 回归：相关模块测试、翻译资源检查、构建与签名校验。既有 Lint 基线保留并报告。

## 实测结论

- 手机 PKX110：该任务的 34 张已登记截图都存在，两个动作的 beforeId 原本为 null。新版连续播放显示 22 张实际动作帧，首张启动画面不再误报缺图。本次无需改动存储队列；真正缺文件、保护页面和解码错误仍按真实状态处理。
- 关键页实际选出搜索结果与报告引用的三篇笔记标题；按真实观测和调用编号关联，没有依据点击数量或等距抽样。
- 报告新增白色文档卡、蓝色状态条、分节/列表层次；根据任务类型突出车次、金额和日期时间，原有推荐标题及重点词使用 Bold。修复中文标点紧贴粗体结束符、末尾多余空格导致的裸露星号。代码片段不改写。
- 用系统文件选择器实际保存 MD、TXT、DOCX；Word 通过 ZIP/XML 检查和 macOS textutil 独立读取，实际导出检查发现结论和日期为加粗 run，未残留 `**`。没有添加文档生成依赖，使用现有 Markdown 模型和 JDK ZIP/XML。
- 回放图像在剩余空间等比适配、完整显示；图片与紧凑控制区同时可见。点击红圈和滑动方向箭头、上下帧、播放/暂停、倍速及弹窗步骤明细完成 ADB 验收。阶段栏跟随当前阶段定位。
