# 手机直连飞书机器人

此功能由手机自己收发消息，不需要电脑桥接、Tailscale、MCP 或公网监听端口。默认关闭；启用后手机显示常驻连接通知。现阶段支持飞书企业自建应用机器人的**文本私聊**，不接收群聊、附件或卡片回调，不支持 Lark 国际版域名。

## 配置

1. 在飞书开放平台创建企业自建应用，添加「机器人」能力。
2. 开通 `im:message.p2p_msg:readonly`（读取用户发给机器人的单聊消息）和 `im:message:send_as_bot`（以应用身份发消息）。
3. 手机 Mika 设置 › 飞书机器人中填写 App ID、App Secret，启用并保存。
4. 飞书「事件与回调」的**事件配置**选择长连接，订阅 `im.message.receive_v1`；在单独的**回调配置**页也选择长连接并添加 `card.action.trigger`（卡片回传交互）。然后发布应用，确保账号在可用范围内。后台可能需要先检测到手机的连接才能保存。仅订阅消息事件时，文字命令可用，但菜单卡片点击不会生效。
5. 手机设置页显示首次绑定码。用自己的飞书账号私聊机器人，发送完整的 `绑定 <绑定码>`。收到确认后，只有该账号在这个私聊中的文本命令会执行。

一个飞书应用只配置一台手机。不要让电脑桥接和手机同时连接同一个应用：飞书长连接多实例会分摊事件，而不是把每条消息广播给所有实例。切换时先停止原电脑桥接。

凭据、绑定、收件记录和送达尝试用 Android Keystore 加密，放在不参与系统备份的目录。更换应用凭据会清除旧绑定；「解除绑定并生成新绑定码」可撤销当前账号的访问权。解除绑定和关闭连接不取消已经交给手机的任务。

## 使用

基于 v0.1.36 原生 `TaskService.startChannel`、任务登记处、消息确认及送达账本。飞书不再只保存一个可执行任务编号，而是保存**当前选择的真实 Mika 对话窗口**；不同窗口的任务由 Mika 原生并行/排队机制调度。未开启并行或达到并行上限时，新任务排队，不会被当成旧任务的追加要求。

发送 `/任务` 后收到菜单卡片：点击下拉框，会弹出所有窗口的标题选项，选择一个进入其详情卡片；点击「＋ 新建任务」进入一个新的空白窗口，再发文字才开始新任务。新建和切换都不取消或修改其他窗口。列表每页 20 项，可翻页；选项同时显示短编号，以区分重名窗口。

窗口列表包含当前安装的 Mika 应用中的手机本地、定时、微信、旧远程及飞书窗口。**已绑定主人明确请求列表或查看时，标题与选中窗口的内容会发送到飞书。** 这不改变电脑任务 API 的可见范围，也不能跨应用读取另一个独立安装的官方版或 Dev 版的数据。

已有手机本地或其他渠道的运行中窗口可以查看；回答、追加、取消只针对本机器人创建且运行编号匹配的任务。空闲窗口可继续新一轮任务，该轮使用外部渠道来源，付款审批和接管边界不变。过期卡片、被删除的窗口和指向已结束运行的取消按钮会拒绝操作，不会落到后来新开的任务上。

直接发文字只在选中的空闲窗口创建任务；收到后由原生任务服务确认一次，普通执行步骤不刷屏。

| 消息 | 用途 |
| --- | --- |
| `帮助` / `/help` | 显示命令 |
| `/任务` / `/tasks` | 按标题列出所有 Mika 窗口，选择、查看或新建 |
| `/新建` / `/new`、`新对话` | 进入新的空白窗口，不影响其他运行 |
| `状态`、`进度` / `/status` | 查询当前选择的窗口 |
| `回复：你的回答` | 回答普通追问 |
| `追加：补充要求` | 向运行中的任务追加要求 |
| `取消` / `/cancel` | 请求取消；随后以任务终态为准 |
| `重试` / `/retry` | 当前窗口提交未确认时，以原窗口、原消息编号和原内容核对或补交 |

多个飞书窗口分别回传自己的完成、失败、取消、追问或接管通知，消息带窗口标题；切换查看目标不改变这些回复的归属。付款确认和接管必须在手机操作，飞书文字不能批准付款或替代接管。运行中发送普通文字只给出提示，不会隐式追加或取消。

「把手机本地及定时任务的最终结果也发送到已绑定私聊」打开时，手机本地任务、定时任务、固定提醒和计划异常的结果也会发送到绑定的飞书私聊。此开关意味着这些结果会离开手机并交给飞书。未满足条件的静默检查不产生结果通知。此功能不会让电脑任务 API 获得手机本地任务的查询或控制权限。

超长答复会截取并提示在手机查看完整内容。窗口详情为主动查询的状态快照；不会持续推送每个步骤。新建的空白窗口在下发首条要求后才由手机登记为真实任务。

## 连接和投递语义

- 连接中断后出站 WSS 自动退避重连，无需配置 webhook 接收地址。网络和操作系统后台限制仍会影响在线情况。
- 事件先持久化再确认；相同消息编号去重，任务编号由应用和消息编号稳定派生。进程重启不盲目重放已开始处理的命令。
- 写入手机任务或飞书消息的响应不明时，先核对原任务。结果不明的飞书发送不自动重发，不承诺跨系统严格恰好一次。令牌获取失败的结果通知会在后续处理时再尝试。
- 重启后先恢复加密收件箱和任务关联，已有任务由手机既有恢复机制报告状态；不从执行步骤中间续跑。
- 启用后请求开机恢复前台服务，但安卓强行停止、厂商后台限制、未解锁或服务启动限制可能阻止恢复；重新打开 Mika，并按系统提示允许后台运行。不能保证关闭屏幕后始终在线。

开发验证需覆盖核心/应用单测及 APK 编译。当前实现仍需真机验证飞书配置、切网、锁屏、重启以及不同厂商的前台服务行为；不能把 JVM 测试当作真机保活验收。
